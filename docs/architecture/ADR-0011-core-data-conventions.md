# ADR-0011 — UUIDv4 keys, timestamptz, and integer-minor-unit money

Status: ACCEPTED
Date: 2026-10-05
Checkpoint: INF-003

## Context

All later domains (credits, subscriptions, tax, payments) share identifiers, time and money representations; choosing once avoids inconsistent tables and costly later rewrites.

## Decision

Primary keys are `uuid DEFAULT gen_random_uuid()` generated by PostgreSQL (UUIDv4; PostgreSQL 17 has no built-in UUIDv7, revisit on PostgreSQL 18). Real-world instants are `timestamptz` with UTC semantics. Money is `amount_minor bigint` plus explicit `currency char(3)`, never floating point; rounding happens once, explicitly, where rates are applied. Banana operational units are plain integers in separate structures and are never money.

## Alternatives considered

- UUIDv7 via extension or application code: better index locality, but adds a dependency or client-trusted generation today.
- Integer serial keys: guessable and unsuitable for external exposure.
- `NUMERIC(19,4)` money: allows fractional minor units and per-row scale drift.

## Consequences

Keys are not time-ordered (slightly worse insert locality than v7). Money arithmetic is exact. Banana credits and money cannot be conflated by type or column.

## Migration / compatibility

No product tables exist yet, so nothing needs conversion. `schema_migrations.version` is a deliberate integer exception.
