## Product direction

Canonical (PRD-TRP-001, `docs/product/BananaGig_PRD_TRP_Alignment.md`; plan in `docs/product/ROADMAP.md`; differences from the PRD v9.4 in `docs/product/PRD_RECONCILIATION.md`): **BananaGig is a neighborhood demand-bundling marketplace.** Customers book eligible services at the current bookable price; as more qualifying nearby bookings join the same provider neighborhood service run (a **BananaDrop**), provider-defined thresholds can unlock lower prices, and eligible existing bookings receive later reductions under explicit price-protection rules. BananaDrop is a first-class core domain, not a later promotion. The domain chain is Category > Service Type > Gig Template > Provider Gig > BananaDrop > Qualifying Booking > Participation > Price Tier > Price Protection; the 20 invariants in the alignment document bind every later checkpoint (a future price is never presented as bookable; demand never creates capacity; the platform, not a client, computes group progress and protected prices; provider role, registration, verification, Go-Live, booking eligibility and BananaDrop eligibility stay separate; Banana Credits are a secondary provider monetization mechanism). Nothing of the BananaDrop domain is built yet: no schema, API or UI exists for it (the configuration scope `DROP` and the template flag `DROP_ELIGIBLE` are only reference metadata). Roadmap order: the provider and supply foundation (PRO-002, PRO-003, CAP-001 to CAP-003, AREA-001), the BananaDrop core (DROP-001 to DROP-010), SEARCH-001 to SEARCH-003, UI-BASE-001 (a retrofit of every existing and future screen to the Apple + Uber Base Web direction; all screens built before it are temporary), the customer experience, booking, then the BananaDrop settlement and lifecycle (DROP-011 to DROP-016).

## Architecture

Modular monolith in a pnpm/Turborepo workspace. PostgreSQL (with PostGIS) is authoritative; NATS JetStream carries events; Valkey, OpenSearch and S3 (SeaweedFS) hold derived data and blobs. Everything runs locally under Docker Compose behind Caddy. See `docs/engineering/APPLICATION_ARCHITECTURE.md` and `docs/engineering/CONTAINER_ARCHITECTURE.md`.
